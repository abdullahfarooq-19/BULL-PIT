Each task is about half a day or less, is one commit when the owner asks for commits (CLAUDE.md), and is ticked only when its check passes. **Code and its tests land in the same task.** After every Python task, `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy bullpit` and `uv run pytest` ("four checks") are clean; after every web task, `npm run lint` and `npm run build` in `web/` are clean too. The diff is re-read for anything the task doesn't need. Pre-commit runs mypy on the whole tree, so a new module is committed together with what it imports (M6 lesson).

**Real services.** Only M11.1-T-3, T-13, T-17 and T-19 touch a real service (T-18, the regression pass, uses fakes only). T-3 and T-17 use the Alpaca **paper** account only (the guard makes anything else impossible), and a pending limit order needs **no market hours** (an order is accepted and queued while the market is closed). Only T-17's second half, one "buy now" market order, needs a US session: 18:30–01:00 PKT until 2026-11-01, then 19:30–02:00. T-13 and T-19 spend Groq tokens: a debated live request costs about 15K, plus about 2.2 to 2.7K once this milestone's text is added (specs-plan §11.5). Nothing else calls an LLM.

**Ahead of this file.** At the owner's request, the probe script `scripts/spikes/alpaca_limit_entry.py` was written and dry-run (it printed its plan and touched nothing) before the documents. It has **not** been run for real. It is committed in T-3.
